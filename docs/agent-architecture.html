Trigger.dev ← 우리 선택

TS task() 함수만 작성·deploy → Trigger.dev의 관리형 컨테이너에서 실행. 타임아웃 없음, 큐·재시도·스케줄·스트리밍 내장, idle 0원.

= 내가 관리 안 하는 "긴 작업용 서버"

👉 정리: Trigger.dev는 호스팅/컴퓨트 플랫폼이야. 서버를 네가 띄우는 게 아니라, 네 함수를 걔네 인프라가 대신 돌려줘. Next.js에서 tasks.trigger("analyze", payload) 한 줄로 호출 → 걔네 컨테이너에서 에이전트가 돌고 → 결과를 Realtime으로 스트리밍해줘.

전체 개요

supalens가 유저 질문을 받아 그 유저의 DB를 LLM이 추론·분석하는 전체 경로. ▶ 재생 또는 "다음"으로 단계별로 보세요.

왜 이 모양인가 (핵심 4)
본체는 Vercel ✗. Agent SDK는 claude 서브프로세스를 spawn + 타임아웃 없는 장수 루프 → 서버리스(800초·휘발 FS)와 충돌. 그래서 Trigger.dev.
Vercel은 얇은 BFF. 인증 + run-token + SSE 릴레이만. DB 시크릿·KMS는 절대 안 둠 → 시크릿 표면을 서버리스에서 제거.
시크릿은 호스트에만. 복호화된 supalens_ro는 에이전트 부모 프로세스 클로저에만 → 모델 컨텍스트·subprocess엔 안 들어감.
런 길이 ⟂ Vercel 캡. 런 수명은 Trigger.dev가 소유. SSE 끊겨도 브라우저가 run_id로 살아있는 스트림에 재부착.
